### Документация

**Что делает шаблон**

Шаблон измеряет показатели скорости сайта в браузерах реальных посетителей и отправляет их в Яндекс Метрику как параметры визита. Лабораторные тесты показывают скорость одной загрузки на одном устройстве, а шаблон собирает данные со всех визитов: с медленным мобильным интернетом, старыми телефонами и тяжёлыми страницами каталога.

| Метрика | Что измеряет | Хорошо | Плохо |
|---|---|---|---|
| LCP | Когда показан главный элемент страницы | до 2,5 с | больше 4 с |
| INP | Как быстро страница реагирует на клики и ввод | до 200 мс | больше 500 мс |
| CLS | Насколько «прыгает» вёрстка при загрузке | до 0,1 | больше 0,25 |
| FCP | Когда появился первый контент | до 1,8 с | больше 3 с |
| TTFB | Когда сервер начал отвечать | до 0,8 с | больше 1,8 с |

FCP и TTFB — дополнительные, их можно включить в настройках.

**Как установить**

1. Создайте тег из шаблона «Core Web Vitals → Яндекс Метрика».
2. Укажите номер счётчика Метрики.
3. Выберите триггер «Просмотр страницы» для всех страниц.
4. Опубликуйте контейнер.

Данные появятся в отчёте Метрики «Параметры визитов».

**Настройки**

- **Номер счётчика Метрики** — счётчик, в который уходят данные. Обязательное поле.
- **Метрики** — только LCP, INP и CLS или все пять показателей.
- **Детализация** — только оценка и значение или ещё и путь страницы. Второй вариант помогает найти конкретные медленные страницы, но делает отчёт объёмнее.
- **Цель при плохой оценке** — идентификатор JavaScript-цели в Метрике. Цель достигается, когда любая метрика получает оценку «плохо». Если поле пустое, цель не отправляется. Цель позволяет сравнить конверсию визитов с медленными и быстрыми страницами.
- **Источник библиотеки** — unpkg.com или cdn.jsdelivr.net. Если один из них недоступен в вашей сети, выберите другой.

**Как выглядят данные**

```
Web Vitals → LCP → good → 1840
Web Vitals → INP → poor → /catalog → 620
```

Уровни: метрика → оценка (`good`, `needs-improvement`, `poor`) → путь страницы (если включена детализация) → значение. LCP, INP, FCP и TTFB — в миллисекундах, CLS — безразмерная величина с тремя знаками после запятой.

**Ограничения**

- Измерения выполняет открытая библиотека web-vitals (лицензия MIT, около 6 КБ), шаблон загружает её с выбранного CDN.
- INP и CLS окончательно известны только когда посетитель уходит со страницы. Если браузер закрыт резко, часть таких замеров может не дойти.
- Некоторые браузеры поддерживают не все метрики, поэтому число замеров по разным метрикам может отличаться.
- Если тег сработает на странице повторно, замеры не задвоятся.

### Обоснование разрешений

| Разрешение | Зачем |
|---|---|
| Загрузка скриптов: `https://unpkg.com/web-vitals@5/…`, `https://cdn.jsdelivr.net/npm/web-vitals@5/…` | Загрузка библиотеки измерений. Разрешены только эти два адреса. |
| Доступ к глобальным переменным: `ym` (вызов) | Отправка параметров визита и цели в Метрику. |
| Доступ к глобальным переменным: `webVitals.onLCP`, `onINP`, `onCLS`, `onFCP`, `onTTFB` (вызов) | Подписка на замеры библиотеки. |
| Чтение URL | Путь страницы для детализации. |
| Хранилище шаблона | Защита от повторной подписки, если тег сработал несколько раз. |

Персональные данные шаблон не собирает и никуда, кроме указанного счётчика Метрики, данные не передаёт.

| Email | **TODO** |

### Документация

**Что делает шаблон**

Шаблон подключает трекер Динамики на сайт и отправляет события в ваш проект. Подходит и для облачной Динамики, и для установки на собственном сервере: события уходят на сервер, адрес которого указан в настройках.

У шаблона два режима:

- **Инициализация** — подключает трекер. Ставится на все страницы.
- **Событие** — отправляет событие с названием и свойствами. Ставится на нужный триггер: клик, отправка формы, специальное событие.

**Как установить**

1. Создайте две переменные-константы: «Ключ проекта Динамики» (в Динамике: Настройки проекта → Ключ проекта) и «Адрес сервера Динамики» (адрес, по которому открывается интерфейс Динамики).
2. Создайте тег из шаблона «Динамика», тип «Инициализация», укажите обе переменные и выберите триггер «Просмотр страницы» для всех страниц.
3. Для каждого события создайте ещё один тег из шаблона: тип «Событие», те же переменные, название события и свойства.
4. Опубликуйте контейнер.

В каждом теге указываются ключ и адрес сервера. Тогда событие отправится, даже если его тег сработает раньше тега инициализации.

**Настройки**

- **Тип тега** — «Инициализация» или «Событие».
- **Ключ проекта** и **Адрес сервера Динамики** — обязательные поля.
- **Профили пользователей** — создавать профили только для идентифицированных посетителей (по умолчанию) или для всех.
- **Автосбор кликов и форм** — Динамика сама фиксирует клики, отправки форм и переходы.
- **ClientID Яндекс Метрики** — прикреплять к событиям свойство `metrika_client_id`. По нему данные Динамики связываются с данными Метрики по одному посетителю.
- **ID пользователя** — идентификатор посетителя в вашей системе, например из переменной уровня данных. Не передавайте в этом поле email, телефон и другие персональные данные.
- **Название события** и **Свойства события** — для типа «Событие». Свойства задаются парами `ключ=значение` через точку с запятой, значения могут содержать переменные ЯТМ: `form=callback; page={{Page Path}}`.

**Если Динамика уже установлена на сайте**

Если трекер уже подключён кодом на сайте или другим тегом, шаблон не загружает его повторно. Он только добавляет ClientID, идентификацию и события к существующему подключению.

**Где хранятся данные**

Трекер загружается с сервера Динамики (`demo.dinamikapro.ru`), а события уходят на сервер, указанный в поле «Адрес сервера Динамики». Если по требованиям безопасности сайт не может загружать скрипты с внешнего сервера, напишите нам: подготовим вариант шаблона, который загружает трекер с вашего сервера.

### Обоснование разрешений

| Разрешение | Зачем |
|---|---|
| Загрузка скриптов: `https://demo.dinamikapro.ru/static/array.js` | Загрузка трекера Динамики. Разрешён только этот адрес. |
| Доступ к глобальным переменным: `posthog` (чтение и запись), `posthog._i` (чтение и запись) | Создание очереди инициализации до загрузки трекера. Трекер Динамики построен на открытой библиотеке posthog-js (лицензия MIT), поэтому глобальный объект называется `posthog`. |
| Доступ к глобальным переменным: `posthog.__loaded`, `posthog.__SV` (чтение) | Проверка, не подключён ли трекер на сайте раньше, чтобы не загружать его повторно. |
| Доступ к глобальным переменным: `posthog.register`, `posthog.identify`, `posthog.capture` (вызов) | Передача ClientID, идентификатора пользователя и событий. |
| Чтение cookie `_ym_uid` | ClientID Яндекс Метрики для связки данных. Другие cookie не читаются. |
| Хранилище шаблона | Очередь тегов, сработавших до загрузки трекера. |
